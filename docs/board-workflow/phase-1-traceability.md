# Phase 1 offline requirement traceability

This ledger maps the Phase 1 safety requirement IDs to host-only tests in
[`tests/test_board_workflow.py`](../../tests/test_board_workflow.py) and
[`tests/test_broker_contracts.py`](../../tests/test_broker_contracts.py). All
listed implemented coverage is **host/offline coverage only**: it does not
access a board and is not evidence of USB, flash, reset, firmware, or physical
behavior. The proposed column records remaining follow-up acceptance coverage;
it is not implemented merely because it appears here.

Test pointers use class and method names so they remain searchable when source
line numbers move. The broker record shapes and limitations are documented in
[`broker-contracts.md`](broker-contracts.md).

| Requirement | Existing implemented host/offline coverage | Proposed coverage — not implemented in this PR |
|---|---|---|
| `USB-01` — no hardware by default | [`BoardWorkflowTests.test_defaults_do_not_execute_hardware`](../../tests/test_board_workflow.py) checks both hardware-capable commands default to dry-run, rejects arbitrary flash arguments, and verifies dry preflight does not call approval, identity, or execution boundaries. [`BrokerContractTests.test_complete_execute_request_validates_without_io`](../../tests/test_broker_contracts.py) validates a complete synthetic admission while a trap rejects any file open. | Trap concrete future transport/device adapters for every non-execute broker operation, malformed request, cancellation, and dry-run path. No adapter exists in T2. |
| `ID-01` — exact physical and endpoint binding | Existing workflow tests reject mismatched, changed, missing, and duplicate synthetic endpoint identities. Broker tests [`test_metadata_only_enrollment_is_candidate_only_and_cannot_execute`](../../tests/test_broker_contracts.py), [`test_reviewed_enrollment_requires_exact_native_usb_identity`](../../tests/test_broker_contracts.py), [`test_scope_challenge_operation_and_identity_mismatches_fail_closed`](../../tests/test_broker_contracts.py), and [`test_required_identity_and_approval_facts_reject_unknown_or_missing`](../../tests/test_broker_contracts.py) enforce candidate-only discovery, exact native-USB identity, exact physical/endpoint scope, and complete concrete facts. | Runtime tests with fake inventories for duplicate VID/PID devices, duplicate serials, moved paths, post-reset swaps, ambiguity, and adapter-versus-DUT confusion remain proposed for the future broker adapter. |
| `AUTH-01` — fresh, one-use, complete scope | Existing [`test_authorization_absent_and_out_of_scope`](../../tests/test_board_workflow.py) rejects missing and manifest-mismatched local approval. Broker tests cover canonical signed bytes/public verification-only dispatch, signer/broker/runtime/config/topology/power/dispatcher/operation/unit/endpoint/challenge scope, strict operations/effects, expiry, five-minute lifetime, trusted-clock and remaining-window rejection. See `test_signature_hook_receives_canonical_plan_and_dispatcher_has_no_signing_key`, `test_scope_challenge_operation_and_identity_mismatches_fail_closed`, `test_expiry_lifetime_clock_and_remaining_window_rejections`, and `test_effects_resets_artifacts_and_unknown_fields_are_operation_exact`. | Atomic consumption, concurrent duplicate dispatch, durable restart/checkout replay prevention, and interrupted consume/spawn are T4 runtime work and remain proposed. T2 defines and signs the unique approval ID but does not claim durable one-use enforcement. |
| `ART-01` — exact build and flash bytes | [`test_artifact_mismatch`](../../tests/test_board_workflow.py) rejects a synthetic artifact whose digest differs from its manifest. Broker contract tests require exact manifest/bundle/source/lock and five-file digests, fixed three-file offsets, settings, and write-only applicability. | Transport-byte validation, stale source/lock lookup, traversal/symlink/truncation/extra-file cases, and replacement races remain T3 adapter work. |
| `OWN-01` — one active lab operation | [`test_contention_snapshot_finds_known_owner`](../../tests/test_board_workflow.py) detects a synthetic known owner; [`test_lock_released_after_exception`](../../tests/test_board_workflow.py) checks cooperating-lock release. | Cross-process, cross-checkout, cross-slot, and resource-contention cases, while retaining the documented limits of process snapshots and cooperating locks. |
| `BOUND-01` — no indefinite or retried action | [`test_build_and_flash_command_failure`](../../tests/test_board_workflow.py) checks command failure and the one-open-attempt environment; [`test_capture_closes_fd_on_error`](../../tests/test_board_workflow.py) checks descriptor cleanup; the serial outcome test covers synthetic timeout/disconnect/cap outcomes. | Hung process trees, local deadlines, output caps, lease loss, cancellation, failed opens, kernel stalls, and proof that no automatic recovery path runs. |
| `TEST-01` — no false fixture PASS | [`test_serial_pass_fail_missing_marker_silence_timeout_disconnect_and_cap`](../../tests/test_board_workflow.py) requires matching BOOT/PASS nonces and covers FAIL, stale PASS, silence, malformed bytes, disconnect, and byte cap. | Split/boundary markers, mismatched nonces, stale streams, crash/noise cases, and explicit prevention of peripheral or performance claims. |
| `EVID-01` — durable record for every admitted attempt | **No existing test method.** The current [`write_result`](../../tools/podlesp_board.py) helper writes bounded JSON, but that is implementation, not tested durability coverage. | Fault injection around consume/spawn, partial journals, disk-full/restart/ACK-loss cases, terminal escaping, and non-replay of admitted unknown attempts. |
| `TOPO-01` — no port or power overclaim | Broker approval tests require concrete topology/power digests and reject admission when either differs from trusted local scope. This validates references only, not their physical truth. | Port accounting and validation of topology/power document content remain proposed; later physical evidence remains separately authorized and separately labelled. |

CI discovers all current pure-Python methods (the original 11 board-workflow
tests plus the broker-contract tests) with the runner's Python 3 before using
the pinned Nix tooling for the bounded smoke build. A passing suite proves only
these offline contracts; the smoke build remains compilation evidence only.
